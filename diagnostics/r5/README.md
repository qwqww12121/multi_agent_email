# R5 Base 提示与最小证据输出诊断

2026-10-29。用户授权：保留 Llama 3.1 Base，只改提示和输出约束，在远端验证。

独立目录，不覆盖 R3/R4，不修改六列正式结果、原生候选标签评分、PPO 或 RAG。

## 受控对照

复用 R4 的四封诊断邮件，每个来源一封；全部保留原文，不添加示例或答案。
这四封邮件已被用于调试，不是新的留出评估集。

四组：plain_free、chat_free、plain_json、chat_json。前两个自由生成；后两个使用同一个最小 JSON schema 限制生成。plain 与 chat 的任务说明、正文、JSON 前缀、采样、预算、停止条件相同，仅消息包装不同。聊天模板直接来自远端 tokenizer，不修改模板。

每封邮件分别调用 action、purpose、persuasion、context 四个角色，共 64 条输出。每次只输出 evidence 字符串（最多 160 字符）。角色分别寻找请求、主题/提议、说服证据、正文中自称身份。证据可为空；不把空证据自动判定为正确。

统一贪心生成、每组四条批处理、最多 160 个新 token，三个停止 token 为 128001/128008/128009；另在 JSON 对象闭合时停止。输入不截断。保留完整提示、生成 token、预填前缀和输出，拒绝修复失败 JSON。

模型加载前沿用 R4 的冻结文件哈希校验。运行配置、输入和脚本哈希参与签名；运行时保存模型身份。

## 验收与解释边界

分别统计：完整对象停止、长度耗尽、schema 合法、非空证据、逐字匹配正文。逐字匹配不等于角色相关，也不代表理解正确；角色相关性另行检查原文。

这是最小能力诊断，输出协议有意简化，与 R4 完整角色报告不兼容。即使全部通过，也不能声称原有完整报告、分类或 PPO 链路通过。

## 实测结果

远端 `/phishing_email/test_1/benchmark_native_20261014/four_text_v4r5_probe_20261029`，RTX 4090，原 Base 文件哈希验证通过。第一轮完成 64 条，生成阶段 73.27 秒（不含模型校验加载）。

- plain_free：16 条中 4 条 JSON 可解析，0 条符合含 160 字符上限的 schema，12 条达到 token 上限。
- chat_free：16 条中 8 条 JSON 可解析，3 条 schema 合格，2 条为非空逐字原文，8 条达到上限。
- plain_json：16/16 schema 合格，2/16 为非空逐字原文，无长度耗尽。
- chat_json：16/16 schema 合格，6/16 为非空逐字原文，无长度耗尽。

以上引用指标不是内容正确率。例如 chat_json 的 context/persuasion 均曾输出 `Hey Adam,`，虽然它在原文里，但不能回答发件人身份或说服策略。多个角色截取正文开头或修改原文空格。结论：聊天模板不能单独解决任务执行；强制 JSON 解决了最小结构闭合，但不保证相关内容。

原始证据见 records.jsonl、runtime.json、status.json、run.log；audit.py 从 raw 重新计算并校验统计，输出 audit.json。

## 自适应追加：短问答与填空

在看到第一轮问题后另做 32 条诊断，仍为这四封邮件，不能视为独立确认实验。脚本 short_probe.py，结果 short_followup/。程序封装输出，模型不用生成 JSON，不再要求逐字摘录；任务改成简短的语义回答，因此其完成率不能直接当作第一轮严格证据合格率比较。

两种形式均为正文后追加一个问题或一个待续写句子，最多 80 token，统一遇回答开始后的首个换行或 EOS 停止。完整保存停止时输出；达到预算仍标记失败。追加生成阶段 18.04 秒，不含加载。

短问答 qa：16 条中 14 条在换行或 EOS 结束，2 条达到上限。能正确概括四封邮件的主题；在 ePhishLLM 中正确回答查看附件并反馈；身份回答中识别 Mike、Josefine、Quien Jelo。仍有失败：Enron 主要请求被归为退订；Kaggle 说服手法输出模板化、无依据的权威/情绪/可信度论述且耗尽预算；Enron 身份虽开头指出 Computron，继续枚举品牌直到耗尽预算。Kaggle 的购买请求是概括推断，不能当作原文摘录；PhishingPot 使用了不准确的男性代词。未建立新的正式人工标注集，故不报告语义准确率。

填空 cloze：出现角色句式续写、重复、无依据的 phishing/盗取信息判断、虚构链接/公司身份等。不能作为可靠替代。

结论：短问答是本次较有希望的提示形式；保留为诊断候选，不升级正式架构。完整报告、证据逐字引用、所有角色可靠性、分类与 PPO 均未通过验收。进程已经退出，检查时 GPU 回到 1 MiB、0% 利用率。
